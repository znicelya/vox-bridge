Translation management API
翻译管理 API

Control the Palabra real-time translation pipeline over WebSockets or a WebRTC data channel.
通过 WebSockets 或 WebRTC 数据通道，实现对 Palabra 实时翻译流程的控制。

Prerequisites  先决条件

  • WebSockets — you only need an API Key. Optionally, you can create a streaming session yourself and use its ws_url and publisher token instead.
    WebSockets——你只需要一个 API 密钥即可。可选地，你可以自行创建一个流会话，并使用其 ws_url 和 publisher 令牌。
  • WebRTC — create a streaming session first. The response contains the webrtc_url (the URL of the Palabra WebRTC Speech-to-Speech Translation API) and the publisher JWT access token used to authorize your connection.
    WebRTC——首先需要创建一个流媒体会话。响应中包含 webrtc_url （Palabra WebRTC 语音转语音翻译接口的 URL），以及 publisher 的 JWT 访问令牌，用于授权您的连接。

Choose a transport  选择一种运输方式。

Option 1. WebRTC  选项 1：WebRTC 技术

  1. Create a streaming session.
    创建一条流式会话。
  2. Connect to webrtc_url with any LiveKit client using your publisher token.
    使用您的 publisher 令牌，通过任何 LiveKit 客户端连接到 webrtc_url 。
  3. Wait for the Palabra translator to join the room — it connects a moment after you do, and your session room contains only you and the translator, so the first remote participant to join is the translator. It may also already be in the room by the time you connect, so check the current participant list before subscribing to the participant-connected event.
    请等待“Palabra”翻译器加入房间——一旦您连接成功后，它就会立即加入房间。此时，您的会话房间里只有您和翻译器而已。因此，第一个加入房间的远程参与者就是翻译器。也许在您连接之前，翻译器就已经在房间里了，所以在订阅参与者事件之前，请先检查当前的参与者列表。
  4. Once the translator is in the room, send commands through the default (empty-topic) WebRTC data channel.
    当翻译器进入房间后，通过默认的（空主题）WebRTC 数据通道发送指令。

A command published before the translator is in the room is not delivered to anyone — the room accepts the data message, but there is no one subscribed to receive it, so the first set_task is silently lost and the translation never starts. See Step 6 of the WebRTC Quick Start for a ready-made wait helper.
在翻译器进入房间之前发布的命令并不会被传达给任何人——房间只是接收到了该数据消息，但并没有人订阅以接收它。因此，第一个 set_task 会被默默地忽略，翻译也就无法开始。如需使用现成的等待辅助工具，请参阅 WebRTC 快速入门指南中的步骤 6。

This applies to WebRTC only. Over WebSockets you talk to the server directly, so set_task can be sent as soon as the connection is open.
这仅适用于 WebRTC 协议。而在 WebSockets 协议中，你可以直接与服务器进行通信，因此 set_task 这样的消息可以在连接建立后立即被发送。

Option 2. WebSockets  选项 2：WebSockets

Connect to the WebSocket endpoint, passing your API Key as the token query parameter (or in the Authorization header). The server validates the key and creates a streaming session for the lifetime of the connection automatically:
请连接到 WebSocket 端点，将您的 API 密钥作为 token 查询参数传入（或放在 Authorization 头部）。服务器会验证该密钥，并会在连接期间自动为您创建一个流会话。

const randomHash = crypto.randomUUID(); // any random URL-safe string
const endpoint = `wss://streaming.palabra.ai/streaming-api/${randomHash}/v1/speech-to-speech/stream?token=${apiKey}`;
const socket = new WebSocket(endpoint);

Replace the {random_hash} path segment with any random URL-safe string generated by your client for the connection — it is used to distribute connections across translation servers.
请将 {random_hash} 路径部分替换为客户端生成的任意随机的、符合 URL 安全规则的字符串。这个字符串用于在不同翻译服务器之间分配连接资源。

Alternatively, create a streaming session yourself and connect to the returned ws_url with the session's publisher token:
或者，您可以自行创建一个流会话，然后使用该会话的 publisher 令牌来连接至返回的 ws_url 。

const endpoint = `${ws_url}?token=${publisher}`;
const socket = new WebSocket(endpoint);

Once the connection is open, you can start sending commands.
一旦连接建立，就可以开始发送指令了。

Message format  消息格式

Every API message — request and response — has the same envelope:
每一个 API 消息——无论是请求还是响应——都遵循相同的格式结构。

{
  "message_type": "<string>",
  "data": { /* payload */ }
}

If message_type is "error", the data field contains diagnostic information.
如果 message_type 等于 "error" ，那么 data 字段就会包含诊断信息。

Typical workflow  典型的工作流程

  1. Create a task — send set_task and wait for task_status with event: "started" and task_status: "running" before sending audio.
    创建一个任务——发送 set_task ，并在收到 task_status 的回复后，再发送音频，同时带上 event: "started" 和 task_status: "running" 的信息。
  2. Update the task — send another set_task to change settings during an ongoing translation.
    更新任务——在翻译进行中，发送另一个 set_task 来修改设置。
  3. Pause processing — send pause_task to pause the translation (billing stops). Resume with another set_task.
    暂停处理——发送 pause_task 以暂停翻译过程（计费将停止）。再次发送 set_task 即可继续处理。
  4. Interrupt processing — send interrupt_task to instantly stop transcription, translation, and speech of the current phrase (e.g. the speaker got interrupted) without pausing the translation of subsequent phrases.
    中断处理——发送 interrupt_task 以立即停止当前短语的转录、翻译和语音输出功能（例如，当演讲者正在讲话时突然中断了对话）。同时，后续短语的翻译将继续进行，不会暂停。
  5. Finish the task — send end_task. No new audio is accepted after it; the server finishes processing everything it already received, sends an end_of_stream message and closes your connection automatically; the session is invalidated within 1 minute.
    完成任务——发送 end_task 。之后将不再接受新的音频文件；服务器会处理已接收的所有数据，发送 end_of_stream 消息，并自动关闭您的连接。该会话将在 1 分钟内失效。

Settings reference  设置参考

  • What each field means — see the Translation settings breakdown.
    每个字段的含义——请参见翻译设置详解。
  • Recommended values — see the Recommended settings.
    推荐值——请参阅推荐设置部分。

超过命令限制会返回 error 消息；超过连接限制则会导致连接关闭，并伴随代码 1008 的提示。

Streaming audio configuration
流式音频配置

Option 1. WebRTC audio I/O
选项 1：使用 WebRTC 进行音频输入/输出

Use the following input/output configuration in your set_task:

{
  "data": {
    "input_stream": {
      "content_type": "audio",
      "source": {
        "type": "webrtc"
      }
    },
    "output_stream": {
      "content_type": "audio",
      "target": {
        "type": "webrtc"
      }
    }
    // ...
  }
}
  1. Publish your microphone track to the LiveKit room.
  2. Subscribe to the translated tracks that Palabra publishes to the same room after you send set_task.

Option 2. WebSocket audio I/O

Use this configuration instead:

{
  "data": {
    "input_stream": {
      "content_type": "audio",
      "source": {
        "type": "ws",
        "format": "pcm_s16le", // or opus, wav
        "sample_rate": 24000,  // 16000 – 48000
        "channels": 1          // 1 or 2
      }
    },
    "output_stream": {
      "content_type": "audio",
      "target": {
        "type": "ws",
        "format": "pcm_s16le" // or zlib_pcm_s16le
      }
    }
  }
}

The output is always 24000 Hz, mono (sample_rate and channels cannot be changed).

  1. Send base64-encoded audio chunks that exactly match the declared format.
  2. Receive base64-encoded TTS chunks in output_audio_data responses (see below).

API messages

Requests (client → server)

get_taskReturn the current task
pause_taskPause the current task; resume with set_task
interrupt_taskInstantly stop the speech of the current (ongoing) phrase
end_taskFinish the translation task

set_task

Create a new task or modify the current one:

  • Sent for the first time after creating a session — starts the translation.
  • Sent after pause_task — resumes the translation.
  • Sent during an ongoing translation — updates the settings in real time, no need to stop the translation.
{
  "message_type": "set_task",
  "data": {
    "input_stream":  { /* Depends on transport — see "Streaming audio configuration" above */ },
    "output_stream": { /* Depends on transport — see "Streaming audio configuration" above */ },
    "pipeline": {
      "transcription": {
        "source_language": "string",
        "detectable_languages": ["string"],
        "segment_confirmation_silence_threshold": "float",
        "only_confirm_by_silence": "bool",
        "sentence_splitter": {
          "enabled": "bool"
         },
        "verification": {
          "auto_transcription_correction": "bool",
          "transcription_correction_style": "string"
        }
      },
      // Translation and speech generation settings for one or more target languages
      "translations": [
        {
          "target_language": "string",
          "translate_partial_transcriptions": "bool",
          "speech_generation": {
            "voice_cloning": "bool",
            "voice_id": "string",
            "voice_timbre_detection": {
              "enabled": "bool",
              "high_timbre_voices": [],
              "low_timbre_voices": []
            }
          }
        }
        // You can add more targets
      ],
      "translation_queue_configs": {
        "global": {
          "desired_queue_level_ms": "int",
          "max_queue_level_ms": "int",
          "auto_tempo": "bool"
        },
        "es": {
          "desired_queue_level_ms": "int",
          "max_queue_level_ms": "int"
        }
      },
      // Select response types to receive
      "allowed_message_types": [
        "translated_transcription",
        "partial_transcription",
        "partial_translated_transcription",
        "validated_transcription"
      ]
    }
  }
}

See the Translation settings breakdown for details on each field and the Recommended settings for best-practice values.

ASR-only mode. To use this API in ASR only mode, do either of the following:
  • Set output_stream to null — you will still get text translations, but no TTS audio.
  • Use an empty translations list — you will get neither text translations nor TTS audio.

get_task

Return the current task (as a current_task response). Set exclude_hidden to false to include advanced (hidden) fields in the response.

{ "message_type": "get_task", "data": { "exclude_hidden": true } }

pause_task

Pause the current task. No audio is processed and no billing applies while the task is paused. Use set_task to resume.

{ "message_type": "pause_task", "data": {} }

interrupt_task

Instantly stop the speech (TTS) of the phrase currently being processed, without pausing upcoming ones. Useful when the current phrase no longer needs finishing — for example, if your conversation partner interrupts you. Unlike end_task, nothing is finalized: the current phrase is dropped.

{
  "message_type": "interrupt_task",
  "data": {
    "languages": ["global"], // 'global' (all languages, default) or target languages from `translations`
    "pause_task": false      // pause the task after interrupting
  }
}

end_task

Finish the current task. After end_task no new audio is accepted; the server finishes processing everything it already received (the tail of the translation is fully delivered), sends an end_of_stream message (see below) and then closes the connection automatically.

{
  "message_type": "end_task",
  "data": {
    "force": false // drop the pipeline and disconnect immediately, without processing the tail
  }
}

tts_task

The tts_task command is temporarily disabled. For text-to-speech, use the dedicated Realtime TTS API, or contact support at support@palabra.ai.

Generates TTS from text within the active task. The behavior depends on translate_text (default false):

  • "translate_text": false — TTS only. language is the language to speak in and must be one of the target_language values configured in the task's translations section (otherwise a VALIDATION_ERROR is returned).
  • "translate_text": true — the text is first translated into every target_language of the task, then synthesized. language is the language of the input text and must be a valid source language.

text is limited to 2048 characters. See the Text-to-Translated-Speech guide for details.

{
  "message_type": "tts_task",
  "data": {
    "text": "Hello, how are you?",
    "language": "en",       // text language
    "translate_text": false // default
  }
}

input_audio_data

Send a base64-encoded input audio chunk when WebSockets is selected as the audio transport. The audio chunks you push must match the format / sample_rate / channels declared in your set_task command. The optimal chunk length is 320 ms. The base64 payload must be between 1 KB and 512 KB (≈384 KB of raw audio per message).

{
  "message_type": "input_audio_data",
  "data": {
    "data": "base64 encoded data"
  }
}

output_audio_data

TTS audio chunk (when WebSockets is the audio transport):

{
  "message_type": "output_audio_data",
  "data": {
    "transcription_id": "190983855fe3404e",
    "translation_part_id": "0",  // part index when a phrase is split into several TTS pieces
    "language": "es",            // TTS language
    "last_chunk": false,         // true on the last generated chunk for this `transcription_id`
    "data": "base64 string",     // ≤512 KB base64 (≈384 KB of raw audio)
    "chunk_generation_delta": 120 // optional, ms between generation start and this chunk
  }
}

The audio is always 24 kHz mono; the encoding (pcm_s16le or zlib_pcm_s16le) matches the output_stream.target.format of your task.

task_status

The server acknowledges each successful set_task, pause_task, interrupt_task, or tts_task command with a task_status message sent over the same connection. pipeline.allowed_message_types does not filter these responses. If a command is rejected, the server sends an error response instead. Your client must handle acknowledgements alongside incoming transcriptions and audio.

{
  "message_type": "task_status",
  "data": { "command": "set_task", "event": "started", "task_status": "running" }
}
Commanddata.eventdata.task_statusMeaning
set_taskstartedrunningThe pipeline has started and is ready to process input
set_taskupdatedrunningThe new settings have been applied
set_taskunchangedrunningThe settings match the running task; no reconfiguration was needed
set_taskresumedrunningThe settings have been applied and the paused task has resumed
pause_taskpausedpausedInput processing is paused; queued output may still arrive
interrupt_taskinterruptedrunning or pausedSpeech output interrupted for the requested languages
tts_taskqueuedrunning or pausedText queued; data.transcription_id identifies its output

Wait for the set_task acknowledgement before sending audio. A resumed response also confirms that the settings supplied in that command have been applied.

interrupt_task leaves a paused task paused. To also pause a running task, set data.pause_task to true in the interrupt_task command. Audio already buffered by the client may still play unless the client clears its playback buffer.

For tts_task, the acknowledgement confirms that the text is queued for processing. Translation and speech generation may still be in progress.

end_task does not return a task_status acknowledgement. Continue receiving messages until end_of_stream, which confirms that the server has finished processing pending input and output. If this processing times out, the server returns error and closes the connection without end_of_stream. With data.force: true, it discards pending work and closes the connection without end_of_stream.

get_task returns a current_task response. The server does not acknowledge individual input audio chunks.

To determine whether settings have changed, the server compares the complete validated configuration, including default values and advanced settings, with the running task. JSON object key order does not matter; array order does. If the configurations match, the server returns unchanged and keeps the existing pipeline and buffers. Sending the same configuration to a paused task returns resumed.

current_task

The response to the get_task command. Contains the current task configuration plus its status:

{
  "message_type": "current_task",
  "data": {
    "input_stream":  { /* ... */ },
    "output_stream": { /* ... */ },
    "pipeline":      { /* ... */ },
    "task_status": "running" // running | paused | unknown
  }
}
The server sends current_task in response to get_task and when a connection attaches to an existing task. To confirm set_task, wait for its task_status response; polling get_task is unnecessary.

end_of_stream

End-of-stream confirmation. Sent after an end_task, once the remaining audio has been processed and delivered; the connection is closed right after.

{ "message_type": "end_of_stream", "data": {} }

warning

Audio stream health warnings. The server monitors the pace of your input_audio_data stream:

{
  "message_type": "warning",
  "data": {
    "code": "AUDIO_STREAM_TOO_FAST", // AUDIO_STREAM_TOO_FAST | AUDIO_STREAM_TOO_SLOW | AUDIO_STREAM_STALLED
    "message": "Human-readable description"
  }
}

Send audio at real-time rate (e.g., one 320 ms chunk every 320 ms): pushing faster, slower, or stopping mid-stream triggers these warnings and degrades translation quality.

error

Validation, authorization, or other kinds of errors:

{
  "message_type": "error",
  "data": {
    "code": "VALIDATION_ERROR",
    "desc": "ValidationError(model='SetTaskMessage', errors=[{'loc': ('input_stream', 'content_type')",
    "msg": "value is not a valid enumeration member; permitted: 'audio'\", 'type': 'type_error.enum'",
    "param": null
  }
}
