# Task 5C deletion completion and retention ruling

This is the constrained I1 repair of the approved recoverable-deletion flow. It changes no public API, product scope, migration, scheduler status writer, engine/worker/queue limit or paid-service policy. Independent technical review has accepted the localized-corruption authority boundary below; final source review remains required.

## Authority and publication

`IndexRepository::publish_plan` passes the actual private owner-issued `PersistedReceipt` to `PublicationPlan::apply`. The owner has already checked the exact `Awaiting` receipt; its bytes cannot change before acknowledgment. Fresh Create publication requires no prior seal, exact intent/descriptor/operation, actual persisted count equal to complete dense staged IDs `[0,count)`, one exact mapping for every row and no extra destination mappings. Full existing survivor/document/chunk/location/source associations remain required. Every deleted target must be absent from all destination mapping states and versions. SQL absence against an arbitrary old seal is insufficient.

Swap, Recovery and fresh Ready all account for the complete admitted same-source cohort in their existing Immediate pointer transaction. Admission before that transaction is visible; admission afterward binds the new pointer. A selected survivor that changed to Deleting still rejects publication. Direct Delete accounts for all valid duplicate operations for its one full target fence/source; it cannot certify another generation's operation from its current receipt. Unindexed deletion uses a typed local domain publication with empty vector work.

Before removing any target domain row, prove that every relevant unresolved operation for that target is included and certifiable by this publication. A valid differently sourced target operation that this plan cannot certify rejects the whole publication before domain/pointer mutation or source retirement. Retain that target, both source/work references and all proof; do not finish the same-source operation and strand its peer. This guard does not turn a same-source receipt into cross-source authority or introduce a multi-source publication.

All candidate jobs are decoded as bounded borrowed payload bytes with exact kind/object/exclusion/input/payload hash. Enumerate terminal retries as well as queued/running jobs. Live Deleting documents, retained work and valid zero-work inputs supply independent references. An ambiguous relevant input/work association rolls back; failed JSON extraction never establishes absence. Fully proved settled history is excluded. Validate all cohort work while documents still exist, then delete each domain document once and certify every operation in the same transaction.

## Bounded durable journal

Use existing `intelligence_meta` with canonical UUID and numeric key components; inspect borrowed bytes before allocation and decode strict canonical records with no unknown/omitted fields. No new table is introduced.

- `knowledge.delete.v1.publication.{publication_uuid}`: typed receipt intent/seal, plan kind, identity/source, total operation count and ordered anchor-batch root. The native receipt is stored once. Source-removal acknowledgment is mutable and separately checked.
- `knowledge.delete.v1.anchor.{publication_uuid}.{batch}`: at most 200 ordered operation/header-hash leaves, bound to the publication's complete ordered root. Stream as many batches as the complete cohort needs; there is no 200-operation acceptance limit or prefix truncation.
- `knowledge.delete.v1.operation.{delete_uuid}`: immutable full DeleteInput, durable job payload hash, original vector count/full root/shared association root, work/file page counts and roots, publication/batch/ordinal binding. Cleanup and terminal-consumption state are separate mutable fields.
- `knowledge.delete.v1.page.{delete_uuid}.{page}`: original fixed 200-row ordinal range, count and operation-independent full association hash; separate acknowledgment flag. Each operation has at most 1,000 work pages.
- `knowledge.delete.v1.files.{delete_uuid}.{page}`: complete bounded original cleanup descriptors (canonical file UUID, generated UUID plus supported extension, original document/version/job association), in at most 100-descriptor pages. Keep the existing 200,000-item cleanup cardinality bound, check the entire set and encoded 64 KiB page bound, and reject rather than certify a prefix.

The jointly committed immutable publication/anchor/header/page records are durable domain authority. The independent anchor leaf rejects replacement of one syntactically valid operation marker; ordered batch/page roots reject missing, foreign or reordered records. Authority does not depend on equality with a destination seal that legitimately evolves during later opens or indexing. Consistently replacing every mutually anchored SQLite record is outside the existing localized-corruption model; these hashes are corruption/association checks, not a MAC for a hostile database owner.

## Cleanup, peers and lifetime

Before physical source retirement, validate every unresolved delete reference and its exact committed exclusion plus retained page evidence. A valid exclusion certificate authorizes eventual source retirement even while a handler is queued/running; absence of a document alone does not. Source work remains until actual reader/engine close and successful managed-generation removal. SQL mapping/seal cleanup starts only after exact work acknowledgments, never as an indiscriminate deletion of another operation's work.

Before managed cleanup, recheck the full certified owner/path association and reject additional target-owned files outside the certified set. After cleanup, verify actual absence of the original generated final and temporary paths, as well as metadata absence. Missing metadata with remaining bytes is not a cleanup receipt. This filesystem check runs outside SQLite under the existing actual operation owner.

Each original work page is revalidated before acknowledgment. Remove mappings by identity/generation/vector/document/version/chunk/hash/published association; remove that operation's exact work rows and mark the page acknowledged atomically. A missing mapping is acceptable only when a peer has the same source, full document fence, count and shared association root and its identical original page was already acknowledged. A present conflicting vector/chunk mapping rejects. An acknowledged flag must agree with absence of that operation's entire original ordinal range; missing page/work records never mean implicit success.

Preserve all peer headers/pages until the complete publication cohort is closed. `DeleteHandler::terminal_tx`, within the scheduler's existing terminal transaction, consumes proved cleanup; it does not write scheduler status. Cleanup before a queued handler runs, or a crash after handler cleanup before scheduler terminal commit, therefore retains the certificate. Reaped completion settles only actual joined work. A consumed flag must agree with validated durable terminal status and completed domain/files/work.

Actual per-job completion uses the private nonmutating `JobReapPort::prove` and owner-issued `JobReapProof`. A claim frame is registered before Running becomes visible; its factory is permanently closed after continuation ownership is reserved. The handler must have actually ended and every issued child scope must release its process/slot before the proof succeeds. Active-map absence and a terminal status are insufficient. Only bounded live frames are retained; pruning and fresh/inert/prior-generation completion use explicit lifecycle authority. Knowledge stores a separate immutable header-bound consumption receipt from that proof and checks it independently of the changing consumed flag. A pending proof retains the certificate; it does not revoke an independently complete source-retirement proof. This adds no scheduler status writer or public API and preserves existing workers/queues/child slots/deadlines.

Consumption and garbage collection are distinct. A settled Direct Delete operation with terminal Failed/Cancelled/Interrupted keeps independently anchored settlement authority while its source remains active. After actual source removal and SQL cleanup, that history can be collected. Fresh local terminal settlement likewise requires its source cleanup to have ended. Validate a closed complete cohort, then remove its headers/pages/batches/publication atomically in one SQLite transaction using bounded borrowed reads; a crash cannot leave an anchor referencing a partially collected cohort.

## Focused implementation units and tests

`knowledge/index/delete_work.rs` owns full row parsing, live/retained/shared roots and exact mapping acknowledgment. `knowledge/index/delete_completion.rs` and its `journal`, `publication`, `files`, `retirement` children own the durable protocol. `knowledge/service/delete.rs` owns live execution and handler terminal consumption; `service/recovery.rs` owns startup/document-gone continuation and witnessed copy. Existing publication/repository/owner/reconcile paths consume the same guards.

Existing whole-document/title/job/byte-boundary fixtures remain passing.
