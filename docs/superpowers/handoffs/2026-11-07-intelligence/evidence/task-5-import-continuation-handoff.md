# Future Task 5 import continuation

Read-only proposal, 2026-11-07; not Task 5A scope or implemented behavior. Consumed baseline is the frozen 5A source over BASE `735284125838e9c1b0fce9a8a4c002482dff281e`.

**Trigger.** ImportHandler's chunk transaction marks Parsed while Import remains Running (`knowledge/documents/handler.rs:49`). Worker separately commits terminal status and removes active membership (`intelligence/jobs.rs:570`). Import/Reindex/Delete share Manual exclusion `document:UUID`; unfinished capacity is 32 (`intelligence/store.rs:49,104`). Thus chunks committed or handler returned Ok cannot trigger Reindex admission. `transition_tx` can change zero rows and still return Ok after shutdown already interrupted the parent; capture the persisted terminal outcome inside that transaction and invoke only after actual committed Succeeded and exclusion release. Leave the SQL-only terminal hook free of ConfigIo.

**Smallest seam: optional AfterTerminal collaborator.** Register once before generation start, retaining unscoped config/storage/events and a validated Reindex registration, never Scheduler/AppState. After successful handler return but before terminal removal, the worker reserves one existing generation child token through a still-active internal JobContext. Carry a compact immutable notice: parent Import id, document UUID/version/SHA256/parser identity. Reservation does not enter ConfigIo. Cancellation/stopping/child-capacity failure drops/skips the continuation without downgrading a successful parse. Invoke once after committed Succeeded; discard otherwise. Await it in the owned worker rather than spawning detached work. Its ephemeral scoped ConfigIo retains the pre-issued token through actual entered completion after timeout/drop; the existing generation drain fences rearm. No token is acquired from a terminal context. Restart leaves an uncontinued Parsed document available for explicit manual Reindex, without automatic paid replay.

**Atomic admission.** Add a narrow config-gated operation reading the selected Embedding setting and its full public profile together; `settings()` followed by `with_profile_snapshot(ids)` has a selection race (`config.rs:245,328`). Under that same ConfigIo gate, enter SQL then generation fence. Recheck parent Succeeded, exact current document/version/hash/parser/import association and Parsed status; skip deleted, replaced, already Indexing/Ready or intervening document work. Admit Manual Reindex and its domain mutation in the same transaction, then publish/wake after commit. Capture the selected profile snapshot in the job; future execution uses 5A's exact credential resolver. A fence alone does not prove Reindex is registered: validate the collaborator's handler capability before start.

**Bounded Notice alternative.** A serialized generation-owned notice consumer can replace the awaited hook if worker throughput requires it. It needs a fixed-capacity queue, acknowledged drain, retained operation/cleanup ownership before parent terminal, and explicit overflow/shutdown semantics. Durable notices additionally require checkpointed storage, consumption and replay policy; do not invent a table or reuse a repair marker. This is more machinery than the one-shot hook.

**Fallback.** No selected Embedding keeps Parsed and the approved “选择 Embedding 模型后建立索引” action. A queue filled after parent release, exclusion conflict or skipped ownership keeps Parsed and exposes a bounded reason with explicit manual Reindex; checkpoint its presentation/storage rather than silently retrying. No unbounded queue/backoff, parent failure or automatic paid retry. Stale notices never alter newer document associations. No source, schema, tests or UI changes accompany this proposal.
