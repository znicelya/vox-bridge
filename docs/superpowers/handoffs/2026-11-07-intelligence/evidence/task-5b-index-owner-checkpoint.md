## Proposed files and ports

Keep `knowledge/index.rs` as the small owner facade, with focused private `index/{owner,repository,codec,preflight,tests}.rs`; later reconciliation/search consume owned ports rather than SrvDB references. One owner thread, one owner-scoped two-worker Rayon pool, bounded command queue16, at most two engine entries keyed by `(identity,generation)`. Each entry records trusted-live status, clean/dirty intent, maintenance lease and last-use state. No callback supplied through the queue can run arbitrary SQLite/config/HTTP code on the owner.

Suggested typed operations: `open`, `add_batch`, `replace`, `delete_batch`, `scan_step`, `search`, `persist_and_seal`, `begin_maintenance`, `copy_step`, `close_generation`; shutdown has a separate retained lifecycle owner. Every request envelope carries a unique operation id, generation fence, already-issued OperationLease, cancellation receiver and reply sender. Closing/queue overflow rejects before enqueue. Observer timeout/drop loses only the reply; the queued/entered envelope retains actual ownership through mutation, persistence and cleanup. A queued cancelled operation may be discarded before entry; entered synchronous library calls finish before acknowledgement. Cleanup continues with an accepted token, never fresh JobContext admission after stopping.

Bound mutation/copy/scan batches to200 records, with vectors exactly identity dimension and metadata<=16384 encoded bytes. Reserve entire add/replace count against200000 including tombstones before calling SrvDB; replacement appends and deletion does not reclaim capacity. Returned ID cardinality must match submitted rows. Failed add/replace may have already appended: classify as dirty, retain intent/owner and reconcile; do not infer rollback. Evidence: pinned `src/engine/write.rs:83–145`, `delete.rs:14–58`.

## Codec and SQLite authority

Metadata schema2/`chunk_location_ref_v1` retains IDs/version/hash and inline nullable page/paragraph/start/end, plus canonical full SQLite TextLocation SHA256. Hash typed compact UTF-8 serde JSON in field order page,paragraph,heading,start_char,end_char with explicit nulls. Never normalize/truncate heading again. Validate strict enum/version/UUID/hash/numeric widths before queueing; enforce serialized byte bounds after encoding. The full location stays in SQLite and returned hydrated hits.

Typed seal root version1 remains<=65536B; dirty intent version1<=16384B. Include exact pinned writer policy, full embedding identity, generation, stored count, fixed filename/length/hash entries; reject unsupported codecs instead of reinterpreting an old generation. Work ids/cursors reference m4 paged work/mapping rows, never unbounded JSON arrays.

Use a typed `IndexRepository` over LocalStore. `DurableIntent`, `PersistedReceipt` and `PublicationAck` have private fields/constructors; ordinary callers cannot supply a claimed clean flag, seal or successful receipt. Repository begin commits the typed intent and work references before issuing DurableIntent. Queue admission and owner execution both revalidate operation id + canonical identity/generation + prior seal hash/current operation state. A descriptor is a fence, not a perpetual authorization. Repository transactions release SQLite before any owner wait, engine call or config access; preserve existing config→SQLite→generation-control ordering and never introduce SQL→config or control→SQL.

The actual owner produces PersistedReceipt only after persistence, bounded validation and streaming seal construction. Future5C uses a typed publication plan to compose seal refresh, mapping/pointer changes and affected Ready state in **one SQLite transaction**, with the same operation/version/generation fence; no separate early Ready publication. Repository returns PublicationAck only after commit. An explicit owner acknowledgment command verifies that ack against repository state before changing its entry from PersistedAwaitingPublication to Clean. If reply/ack is lost, keep the entry dirty; a bounded repository lookup may recover the exact committed acknowledgment, never infer it from persist success. A mismatched/stale acknowledgment cannot clean another operation/generation. No arbitrary closure/callback enters the owner queue.

LRU evicts only clean, unleased entries. If the two-engine budget is occupied by dirty or maintenance-leased entries, return Busy. A typed local persist/reconcile plus fenced repository publication/ack may make an entry clean; otherwise retain it, never silently drop/reopen dirty bytes to create capacity. Dirty intent, engine provenance and document readiness remain separate states.

Managed generation paths derive exclusively from a validated64-lowercase-hex identity and canonical UUID under the managed index root; filenames are fixed allow-list literals. Document titles, source names, metadata strings and caller-supplied relative paths never select generation or cleanup paths.

## Safe open and owner phases

Before SrvDB constructor, enforce accepted regular-file/path/header/count/cap/allow-list policies and verify trusted SQLite seal lengths/hashes with bounded streaming buffers. Fresh creation is only a unique empty managed directory authorized by a durable creation intent. Mark dirty/open intent before constructor; open itself upgrades/creates/truncates/loads tombstones and graphs (`src/engine/open.rs:15–16,55–61`; `storage/metadata.rs:26–70,249–253`). Run every constructor, Auto selection, search, mutation, persistence and engine drop inside the scoped pool/owner lifetime.

Existing unsealed/dirty-on-restart bytes are never passed to the constructor. Keep originals/SQLite text and require explicit repair. Present graph requires trusted bounded-writer provenance and accepted envelope; arbitrary postcard decode is not a preflight. Missing graph may rebuild only from verified unchanged sealed base files. Live partial-persist retry retains its trusted engine and operation: commit can fail after metadata durability (`src/engine/commit.rs:24–34`). A generic drop/reopen retry is unsafe under the accepted restart policy.

After successful persistence, bounded validation and streamed hashes run under maintenance fencing, then the coordinator publishes. Healthy current documents may still search on trusted-live dirty sources through serialized requests and authoritative mapping hydration; persisted dirty alone is not trusted-live authority. A source maintenance lease fences mutation/remap/LRU close across scan/copy steps. Cursor snapshots inspect checked half-open0..count in200-ID pages; missing live metadata differs from tombstone. Borrowed vectors never escape the step: copy immediately, preserve f32 bits, then release slices before destination writes/yields. Auxiliary VectorStorage opens only an existing persisted source under its retained SrvDB lock. Evict the other idle identity before source/staging overlap; never a third engine, second source SrvDB or bare compact.

## Lifecycle decision requiring acceptance

Per-request Task5A tokens are insufficient ownership for **idle cached engines**: retaining a job child token in a cache would prevent scheduler drain, while dropping every process lease after a request could release app.lock before cached mappings are dropped. The index worker needs its own base process lease independent of job child slots.

Root's favored pending-checkpoint form is `IndexOwner::new(data_dir, Arc<LocalStore>)` (or an equally narrow GenerationRepository), inert until `start_owned(base_process_lease)`. The owner worker retains that independent base lease through cached engines and cleanup; idle engines never consume job child slots. SQLite intent/receipt methods must be narrow and bounded, with no config/HTTP callbacks. This explicitly refines the full brief's constructor-start wording; no source implementation is authorized yet.

New performs no spawn or engine open. Owned-start serializes Idle→Starting(generation-id), spawns exactly one owner thread, builds its two-worker pool there, and reports bounded readiness/completion. Repeated start during Starting observes the same generation; Starting/Stopping cannot spawn a replacement. OS spawn failure clears only its own generation state and releases the unstarted closure lease. Pool/startup failure rejects readiness but retains the owner until any partially-created workers are terminated/joined. Retain exactly two pool-worker JoinHandles through a controlled Rayon spawn handler; do not equate dropping ThreadPool with verified OS-thread exit. No engine request enters before successful readiness.

The worker owns the receiver, engine map, pool/worker handles and its base process lease, **no facade Arc or command sender**. Never expose command senders to callers: admission checks state and try_send under one short facade lock; owned envelopes cross the channel. The last facade sender can therefore disappear and let the receiver drain to EOF after AppState destruction. No async observer drop can discard an entered envelope or move SrvDB destruction to an async caller. Engine/auxiliary-reader drop occurs on the owner, then pool termination and worker joins, then that worker's lease release and thread exit. An independent join-owner lease remains until actual owner JoinHandle::join, as specified below; old generation receipts cannot retire a newer generation.

**Chosen join mechanism for root acceptance:** each generation has exactly one non-cloneable `JoinPayload { owner_handle: Option<JoinHandle<...>>, base_lease: Option<OperationLease>, completion_sender }`, initially held by facade lifecycle state. Its base lease is independent of the worker's clone and job-child slots. The first stop/final facade Drop removes the payload under the lifecycle mutex, closes/takes the command sender, releases the mutex, then attempts one `std::thread::Builder::spawn` join coordinator. Repeated shutdown sees only the same completion receiver, so cannot spawn another coordinator. The coordinator performs **only** owner_handle.join, maps completion/panic outcome, drops its base lease, then publishes done; it runs no SrvDB/SQLite/config work. At most one transient join thread exists per stopping generation, outside the unchanged one-owner-plus-two-Rayon execution pool.

`JoinPayload::finish` takes its handle exactly once, joins, releases base_lease and publishes completion in that order. Its synchronous Drop invokes the same finish when a handle remains. Therefore a coordinator spawn failure (the moved closure/payload is dropped) falls back to joining on the initiating thread; there is no Tokio dependency and no abandoned handle during runtime teardown. This fallback may wait for actual entered work and cannot claim an observer deadline or interrupt the library. Normal observer timeout/drop never owns or destroys JoinPayload. A failed initial owner-thread spawn has no handle: release its unstarted leases and return failure. Pool/startup failure has a real handle and follows the same retained stopping/join path; an unobserved failure remains owned until a later observer/close/facade Drop initiates retirement. No successful readiness/rearm is published before the prior failed owner is joined.

Shutdown coalesces by generation id: Running/Starting→Stopping once, rejects new facade admission, drops its command sender when cleanup admission is legitimately closed, and observes the retained completion. A caller timeout returns a pending/interrupted observation without clearing state, freeing engines or enabling restart. Repeated shutdown observes the same owner. Facade Drop closes its sender and transfers/retains join responsibility, never abandons live handles; background work still owns the base process lease until real cleanup.

An accepted multi-phase operation needs a retained work ticket carrying its existing child token through owner mutation, SQLite publication and any cleanup continuation. Request envelopes clone that token. A later handler cleanup hook uses the retained ticket/cleanup owner after active-map removal; it cannot acquire a replacement token from its terminal JobContext. Bound retained tickets by the accepted child-operation/queue limits, avoid handler→scheduler/AppState cycles, and retain the old engine on uncertain persistence instead of evicting it as clean.

AppState start captures an open host epoch and the actual base process lease under its existing admission guard, admits owned index startup, then waits readiness without holding that guard. Recheck the host epoch before enabling jobs/model requests; if close won, startup remains owned and joins the coalesced shutdown path rather than enabling workers in a closing window. Pool/start failure leaves jobs unstarted and reports a safe failure; a retry waits prior owner retirement.

AppState close first fences host/model admission and signals jobs. Keep index cleanup admission available until **jobs.shutdown succeeds**, which includes Task5A child drain; then acquire **all16 direct AppState intelligence-operation permits**, retaining that barrier through index shutdown. These are distinct from the16 job-child slots. Only after both drains may close fence/drop the index sender, await accepted request completion, engine/pool drop and owner join. A jobs observer timeout leaves index cleanup admission available for retry. A direct-operation or index-shutdown observer timeout likewise keeps close unsuccessful and rearm fenced. Do not hold SQLite/config/control locks across these waits.

Reopen requires the existing successful close acknowledgement, then a fresh index worker generation before jobs rearm. Last-AppState destruction drops its facade references; accepted jobs/cleanup tickets retain only necessary ports/tokens until completion. When the last command sender disappears, the receiver drains queued envelopes and closes engines under its independent base process lease. No worker→facade/sender cycle may keep this EOF path alive forever. Root must accept these AppState start/close/rearm/drop seams before 5B source wiring.
